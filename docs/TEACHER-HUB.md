# Teacher Hub, RETIRED 2026-08-07

**This dashboard no longer exists.** `teacher/dashboard.html`, its access gate
`teacher/index.html`, the renderer `assets/js/teacher-dashboard-renderer.js`,
and the Google Apps Script analysis layer under `tools/teacher-hub/` were all
removed on 2026-08-07, the same day the Google Form was retired.

Nothing in this file describes live behavior. It is kept for the same reason
`docs/FORM-CONTRACT.md` is kept: the reasons a tool was removed are the design
constraints on whatever replaces it.

---

## WHY IT WAS RETIRED

**Its only data source was killed the same day.** The Hub's live mode fetched a
Google Apps Script web app that read the `Form Responses 1` sheet. The form that
filled that sheet is gone (see `docs/FORM-CONTRACT.md`), so the sheet will never
receive another row. Every number the Hub could show was frozen at whatever the
last submission happened to be. A dashboard that cannot go stale visibly is
worse than no dashboard, because it looks like it is telling you something.

**Its default mode was fabricated data.** Until a teacher pasted and saved an
endpoint, the Hub rendered a mock class of 28 responses, an 82 percent
completion rate, and four invented students. One of those fixtures was
internally contradictory, `Student C` carried the status `Low` next to the note
"Strong historical context and clear tradeoff." A tool whose out-of-the-box
state is convincing fake class data is a trap in a room where a teacher is
making instructional decisions in the five minutes before a bell.

**The analysis endpoint was public and returned named students.** `doGet()` in
`Code.gs` took filters off the query string and returned the full filtered row
set, including `studentName` and `studentResponse`, as JSON with no
authentication. The deployment instructions told the teacher to deploy it as
"Anyone with the link." The Hub then cached that URL in `localStorage` on a
public GitHub Pages origin. This was flagged in the same privacy review that
closed out the form.

**Its access gate was decoration.** `teacher/index.html` compared a typed code
against the string `song11`, hardcoded in client-side JavaScript on a public
static site, then set a sessionStorage flag that `dashboard.html` checked. Both
halves were readable with View Source. The page said so itself in a notice box,
which is the tell that it was never meant to survive to a classroom.

**It covered one topic out of 77.** Every unit and topic dropdown past
`1.1` was `disabled` and labeled "Coming Soon." Two of those coming-soon labels
had been sitting there since the prototype was written.

## WHAT REPLACED IT

Two separate things, because the old Hub was two tools wearing one page.

**For student work:** Canvas. `docs/CANVAS-CAPTURE.md` describes the pipeline.
Both renderers assemble every response into one document with a machine-readable
record footer, the student pastes it into a Canvas Text Entry assignment, and
`scripts/parse-canvas-submissions.js` turns a Download Submissions folder into a
long-format table plus an exceptions report. Identity comes from the Canvas
roster instead of a text box, and every response that should exist and does not
gets an exception row rather than silently reducing the denominator.

**For the build inventory:** `docs/command-center.html`, backed by
`assets/data/project-status-manifest.js` and regenerated by
`node scripts/generate-status-manifest.js`. That was always a different tool
from the Hub. It reads the repository rather than a spreadsheet, so it cannot go
stale without someone noticing the files moved.

## WHAT WAS KEPT, AND WHY

**`assets/data/teacher/teacher-1-1-song-china.js` survives.** It was the Hub's
data file, but most of what is in it is curriculum, not plumbing: the Topic 1.1
pacing guide, the three learning objectives with their key concepts, the
illustrative example list, five misconceptions with corrections, three sample
strong SAQ responses, three copy-ready AI analysis prompts, and the Canvas
workflow language. None of that depended on the Google Form or the Sheet, and
none of it is recoverable by regenerating anything. Deleting a dead pipeline is
not the same act as deleting a teacher's written pedagogy.

The fabricated parts were stripped in the same pass, for the reason given above.
Removed: `stats.studentResponses`, the `classPulse.summary` block of invented
totals and percentages, and the four `students` fixtures. What remained of
`classPulse` (the anticipated common evidence, the misconceptions to watch for,
and the reteach moves) is real planning content and was renamed to `reteachPlan`
so that no future reader mistakes a planning list for a measurement.

The file has no consumer right now. That is deliberate. It is content waiting
for a surface, not a surface waiting for data, and that is the correct direction
for this dependency after what happened to the last one.

**`assets/css/behistorical-teacher-hub.css` survives.** It is a generic
teacher-surface stylesheet (the purple not-for-students banner, the top nav,
panels, tables, accordions, metric tiles) with nothing form-specific or
Hub-specific in it. Deleting it would have made the next teacher-facing page
re-derive the same rules.

## IF YOU ARE THINKING OF BUILDING ANOTHER TEACHER DASHBOARD

Read the failure list above first. Three of the five failures were not about the
data source at all, they were about a prototype being left reachable at a stable
URL after the thing it prototyped had moved on. The specific rules that follow
from this:

1. **No page shows a number it cannot re-derive on load.** If the source is
   unreachable, the page says so instead of showing the last thing it saw.
2. **No mock data in a shipped surface.** An empty state is honest. A sample
   class is not.
3. **Nothing student-identifying crosses an unauthenticated endpoint.** The
   parser in `scripts/parse-canvas-submissions.js` reads and writes local files
   only, on purpose.
4. **A gate written in client-side JavaScript on a static host is not a gate.**
   If a surface genuinely needs to be teacher-only, it does not belong on GitHub
   Pages.

## THE GOOGLE SIDE, OBSERVED 2026-08-07

Deleting `Code.gs` from this repository did not undeploy anything. The live state
was read off the teacher's Google account and is recorded in full in
`docs/FORM-CONTRACT.md`. The part that belongs here:

The Apps Script project is named **BeHistorical Teacher Hub Analysis**. Its only
trigger is a simple `onOpen`, and it had been **failing on every run** for at
least a week before the retirement, which is a fair summary of the tool's last
months: the dashboard was not merely stale, its analysis layer was erroring and
nobody saw it, because a failing simple trigger reports to nobody.

A second project, **BeHistorical Script ReBind**, sits alongside it running
`onFormSubmit`. It was never in this repository and its purpose is unknown. It
is the form's problem rather than the Hub's, but anyone cleaning up one will
meet the other.
